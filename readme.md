### Дүгнэлт
Энэ лабаар тестийн сценарио бичиж, түүнийг k6 тестийн програмаар биелүүлж хийж үзэв.1

Энэ ажлийн хамгийн хэцүү хэсэг нь тестийн сценариог анх бичэх шат байв.2 Учир нь системийг судалж, мэдэж байж сценариог бичих хэрэгтэй байсан учираас.3 Үүнээс SLO-г асуудалгүй гарган үүсгэсэн. SLO-s k6 тестийн threshold болгоход мөн асуудал гараагүй; зарим threshold-уудад tag бичэн бүлэглэсэн.

Chaos туршилтад availability хэмжүүрийг хугацаа/хэмжээний ялгаатай байсан ч давав (харин reliability threshold-ийг давсангүй). Учир нь сценариод availability тоог харьцангүй их хэмжээтэй бичсэн учир. Энд гарах хугацаа/хэмжээний ялгаа нь 10с-н цонхонд их хэмжээний алдаатай хүсэлт ирж, буцаж, тоо нь зөрөөтэй болдог.



### SLO Үндэслэл

- cart/add -н p95 < 5 (lокал сервер учир маш хурдан)
- /report p95 p95 < 400 (хамгийн муу үед 400)
- /pay error rate < 7% (сервер 5% алдаатай)
- 85%-ийн аvailability (error budget-с ойролцоогоор 2х дахин)
